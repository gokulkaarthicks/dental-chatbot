Flat package of one-domain-per-file services under `backend/app/services/`, each exposing pure functions that take a SQLAlchemy `Session` plus typed input dataclasses and return dataclasses or dicts — no ORM persistence inside the files themselves (models live in `app.models`). Internal layering:
- Shared concurrency primitives: `transactions.py` provides `write_transaction` / `fresh_write_transaction` using `BEGIN IMMEDIATE` to serialize SQLite writers and avoid the deferred-transaction race window; callers wrap every mutation.
- Read-only scheduling core: `availability_engine.py` implements `search_availability`, `is_interval_bookable`, and family-plan search (`search_back_to_back_plans`, `search_nearby_family_plans`) over `AvailabilitySlot`/`SlotClaim`; it delegates provider eligibility to `provider_rules.py` and preference parsing to `date_parsing.py` + `date_phrases.py`.
- State-machine domains: `staff_handoff_board.py` defines alert/request transitions via `ALERT_TRANSITIONS` / `REQUEST_TRANSITIONS` dicts and derives `approval_required` from request type rather than storing a mutable flag; similar pattern appears in other status-driven services.
- Cross-cutting helpers: `audit.py` records actor/entity/action rows, `security.py` guards access, `seed.py`/`reset.py`/`demo.py` populate test data, `scheduling.py`/`appointments.py`/`booking_policy.py` own the write path that consumes the availability engine.
Dependency direction is inward: services depend on `app.models`, `app.timeutil`, `app.observability`, and sibling services (e.g. `availability_engine` → `provider_rules`, `date_parsing`); nothing in this package imports from API routes or controllers.
