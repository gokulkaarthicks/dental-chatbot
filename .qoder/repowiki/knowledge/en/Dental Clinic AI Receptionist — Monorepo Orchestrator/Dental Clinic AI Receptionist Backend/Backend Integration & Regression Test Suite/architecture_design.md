Tests are organized as one pytest module per feature area (reschedule workflow, slot routing, time re-ask replay, family scheduling requests, emergency contacts, etc.) under `backend/tests/`. Shared test state is centralized in `conftest.py`, which exposes a `scenario` fixture that spins up an isolated SQLite file via `app.db.create_db_engine`, injects it into `app.db._engine` / `_session_factory` / `get_engine` / `database_path` for the duration of each test, seeds a Provider + AppointmentType + verified Patient + Conversation, and populates a two-week grid of `AvailabilitySlot`s. Individual test modules may define their own fixtures (e.g. `test_reschedule_workflow.py`'s `db` fixture and `World` helper class) following the same pattern: create a temp SQLite engine, monkey-patch `app.db`, build tables with `Base.metadata.create_all`, seed data, yield to the test, then restore globals and dispose the engine. Tests drive the real service layer (`app.agent.tools.execute_tool`, `app.services.scheduling.Requester`, `app.services.proposals`) rather than mocking them, so they validate end-to-end tool execution and atomicity guarantees against a real DB.
