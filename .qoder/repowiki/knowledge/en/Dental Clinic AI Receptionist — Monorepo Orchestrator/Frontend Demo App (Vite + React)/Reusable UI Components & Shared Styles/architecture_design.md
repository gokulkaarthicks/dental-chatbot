Two parallel concerns live side by side:
- `components/` holds pure presentational React components with no routing or data-fetching of their own. Top-level primitives (`Button`, `Card`, `Stat`, `StatusPill`, `Loading`, `HoursList`) are reused everywhere; `AppShell` provides the app chrome (header/nav/footer) and pulls branding via the shared `useClinicName` hook. The `cards/` subdirectory is a small domain layer: `CardStack.tsx` is the central dispatcher that coalesces `slot` cards into one grid and routes each other `ChatCard` variant to a dedicated view (`ProposalCardView`, `SlotCardView`, `StatusCards`). Handlers flow downward through a single `CardHandlers` interface so stateful callbacks stay in parent screens.
- `chat/` contains the message composer and bubble, integrating with the external `useDictation` hook for speech-to-text input.
- `styles/global.css` defines the entire design system as CSS custom properties (neutral ramp, accent, status hues, spacing/radius scales, typography) consumed by every component class; `cards.css` and `chat.css` add component-scoped styles. There is no CSS-in-JS — styling is purely class-based BEM-style selectors over the token variables.
