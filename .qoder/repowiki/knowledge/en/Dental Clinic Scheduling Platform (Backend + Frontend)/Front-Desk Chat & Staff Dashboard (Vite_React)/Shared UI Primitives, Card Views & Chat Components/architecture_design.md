Two parallel concerns sit side by side under `src/`:
- `components/` is a flat collection of pure presentational React primitives (`Button`, `Card`, `Stat`, `StatusPill`, `Loading`, `HoursList`) plus the app chrome in `AppShell.tsx`, which renders header/nav/footer and pulls branding via the shared `useClinicName` hook from `../hooks`. The `cards/` subdirectory forms a small domain layer: `CardStack.tsx` is the central dispatcher that coalesces all `slot` cards into one grid and routes every other `ChatCard` variant to a dedicated view (`ProposalCardView`, `SlotCardView`, `StatusCards`). Handlers flow downward through a single `CardHandlers` interface so stateful callbacks stay in parent screens.
- `chat/` contains the message composer and bubble, integrating with the external `useDictation` hook for speech-to-text input.
- `styles/global.css` defines the entire design system as CSS custom properties on `:root` (neutral ramp `--c-*`, accent/clay, status hues `--ok-*`/`--warn-*`/`--danger-*`, spacing/radius scales `--s-*`/`--r-*`, typography tokens) consumed by every component class; `cards.css` and `chat.css` add component-scoped styles. There is no CSS-in-JS -- styling is purely class-based BEM-style selectors over the token variables.
