Three cooperating layers with a strict one-way dependency direction `hooks → api` and `hooks/lib → api`:
- `api/` -- two typed fetch wrappers. `client.ts` is the patient client (bearer token via `X-Patient-Session`, idempotency keys on scheduling mutations) exposing `chatApi`, `schedulingApi`, and `api`. `staff.ts` is the Phase-4 staff dashboard client using HttpOnly cookies + CSRF (`X-Staff-CSRF` from the readable `mb_staff_csrf` cookie); it re-exports `ApiError` from `client.ts` so both share one error type.
- `lib/` -- pure data types and cross-cutting runtime. `cards.ts` defines the discriminated union of `ChatCard` variants (`slot`, `proposal`, `family_option`, `confirmation`, …) that travel between backend and UI. `sessionStore.ts` persists only pointers (token, active conversation id, reset generation) in `sessionStorage` per tab; `clinic.ts` memoises the clinic name across components; `liveCards.ts` reconciles prose with server-built card grids.
- `hooks/` -- React composition layer. `useChat.ts` owns the full conversation state machine (bootstrap, restore, optimistic send, demo-reset detection, new conversation). It delegates interactive-card logic to `useCardActions.ts` (slot holding, proposal confirm/decline/change, availability re-sync, grid settlement) to avoid circular references. Supporting hooks: `useApi.ts` (generic abortable loader), `useClinicName.ts` (reactive clinic branding), `useDictation.ts` (browser SpeechRecognition wrapper), `useResetGeneration.ts` (generation diff for overview).

Dependency direction is one-way: hooks import from `api/*` and `lib/*`; nothing in `api/` or `lib/` imports React. The module-level boot guard (`bootPromise`, `bootedMessages`) in `useChat.ts` deduplicates React 18 StrictMode's double mount so the server sees exactly one session per page load.
