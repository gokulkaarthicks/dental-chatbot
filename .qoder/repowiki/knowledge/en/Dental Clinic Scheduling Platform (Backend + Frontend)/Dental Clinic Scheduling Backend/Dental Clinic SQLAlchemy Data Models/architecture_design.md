Models are split by domain area into sibling modules (`patients`, `scheduling`, `proposals`, `conversations`, `family`, `staff`, `sessions`, `operations`), each importing only from `app.models.base`. `base.py` defines the single `DeclarativeBase`, the `TimestampMixin` (created_at/updated_at using a custom `UTCDateTime` TypeDecorator), and every domain enum (`SlotStatus`, `AppointmentStatus`, `ProposalStatus`, `ConversationStatus`, `MessageRole`, `StaffRole`, `AlertKind/Status`, `RequestType/Status`). Cross-model relationships use lazy `TYPE_CHECKING` imports to avoid circular imports. `__init__.py` is the package entry point: it re-imports every model module as a side effect so that `Base.metadata.create_all` discovers all tables without Alembic, and re-exports the public class names in `__all__`. Database-level constraints (`CheckConstraint`, `UniqueConstraint`, partial unique indexes via `sqlite_where`) enforce business rules such as one active claim per slot and positive appointment durations.
