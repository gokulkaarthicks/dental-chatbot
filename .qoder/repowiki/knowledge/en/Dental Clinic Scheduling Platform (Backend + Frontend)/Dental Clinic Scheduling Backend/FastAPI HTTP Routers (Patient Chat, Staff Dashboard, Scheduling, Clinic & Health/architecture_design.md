Each file under `app/api/` defines a FastAPI `APIRouter` with its own `prefix` and `tags`, then is re-exported from `__init__.py` (`chat`, `clinic`, `demo`, `health`) so the app factory can mount them at the application root; `staff.py` and `scheduling.py` are not re-exported there because they require authentication.

- Authentication boundary: `deps.py` centralizes all identity resolution. Patient routes depend on `CurrentPatientSession` (annotated `Annotated[PatientSession, Depends(get_patient_session)]`) which reads the `X-Patient-Session` header via `PATIENT_TOKEN_HEADER` and rejects any `X-Staff-Session` header outright. Staff routes depend on `CurrentStaffSession` / `CurrentStaffUser`, which resolve an HttpOnly `mb_staff_session` cookie plus a matching `X-Staff-CSRF` header for non-safe methods, enforcing SameSite=Lax and rejecting disabled accounts.
- Dependency direction inside the module is strictly one-way: route handlers → `app.api.deps` → `app.services.*` → `app.models`; routers never import each other's routers.
- Blocking work (LLM calls in `runner.run_turn`, heavy service queries) is offloaded from the async event loop via `starlette.concurrency.run_in_threadpool`, wrapping a local `work()` closure that owns the transaction and calls `db.commit()` explicitly.
- Domain mutation errors raised by services (`StaffActionError`, `HandoffError`) are translated to HTTP status codes through a shared `_action_error` helper in `staff.py` rather than being caught inline per handler.
- Request bodies use local Pydantic `BaseModel` subclasses defined near the router (e.g. `LoginRequest`, `SlotSelectionRequest`, `ProposalActionRequest`) with `Field(...)` validators, keeping schema definitions co-located with the consuming route.
