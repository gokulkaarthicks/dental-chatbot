The module is organized as a thin bootstrap stack layered around a single FastAPI app factory:
- `server.py` is the container/module entry point that launches Uvicorn against `app.main:app`.
- `main.py:create_app` constructs the FastAPI instance, installs raw ASGI middleware for request-id propagation/timing/structured error responses, registers CORS (allowing only explicit headers like `X-Patient-Session`, `X-Staff-CSRF`, and the request-id header), includes the six API routers under `/api`, and on startup calls `bootstrap.bootstrap_database()`.
- `bootstrap.py` owns the lifecycle contract: `create_schema()` creates missing tables via SQLAlchemy `Base.metadata.create_all`, then delegates to `migrations.apply_additive_migrations` inside a transaction; `bootstrap_database` also ensures generation metadata and auto-seeds only when the database is empty.
- `db.py` provides a process-global SQLAlchemy engine built with `NullPool` (so the reset path can drop the file without stale pooled handles) and a `session_scope()` context manager that commits on success and rolls back on any exception; per-connection pragmas (`journal_mode=WAL`, `foreign_keys=ON`, `busy_timeout=5000`, `synchronous=NORMAL`) are applied via a `connect` event listener.
- `migrations.py` implements an additive-only reconciler: new columns come from `_ADDED_COLUMNS`, indexes from `_REQUIRED_INDEXES`, both checked against the live inspector before DDL. The one non-additive change -- adding `rescheduled` to the `appointments` CHECK constraint -- is handled by `_rebuild_appointments_table`, which renames the table, recreates it from the model SQL, copies rows, drops the old table, and re-applies indexes.
- `seed_fixtures.py` defines frozen dataclass fixtures (`ProviderFixture`, `PatientFixture`, etc.) as module-level tuples and bundles them into a single `SEED_PLAN`; dates are anchored to the next Monday so repeated seeds produce identical layouts.
- `config.py` exposes a frozen `Settings` dataclass loaded from `.env` (parsed by a minimal in-house dotenv parser, no `python-dotenv` dependency) then overridden by environment variables, cached via `@lru_cache(maxsize=1)`.
- `cli.py` registers `init`, `seed`, `reset-demo`, and `demo-status` subcommands through `argparse`, dispatches them via a `COMMANDS` dict, and each command returns an integer exit code.

Dependency direction is strictly downward: server → main → bootstrap → db/migrations/seed → models/services; nothing in this stack imports back into the HTTP layer.
